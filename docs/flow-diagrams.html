TIME SOURCES

三种时间源

  • 数字时钟: Date() → 1ms 刷新 → = 系统时间
  • 模拟时钟: Date() → 10ms 刷新 → = 系统时间
  • NTP 校准: Date() - offset → NTP 标准时间
底层: Date() → gettimeofday()
            → mach_absolute_time()
            → 内核时钟 (所有页面共用)

差异仅在:
  刷新频率 (1ms vs 10ms vs 120fps)
  显示精度 (秒 vs 毫秒 vs 纳秒)
  校准偏差 (NTP offset)

PRECISION LIMITS

精度瓶颈分析

  • Timer.publish 精度: ±5ms（受系统调度）
  • CADisplayLink: 与屏幕帧率同步 (±0ms)
  • DateFormatter: ~1ms 格式化开销
  • SwiftUI 渲染: ~1-3ms 管线延迟
  • NTP 网络: ±10-50ms（取决于网络）
实际精度链:
  gettimeofday()  ~0.001ms  ← 最精确
  Date()           ~0.001ms
  Timer trigger    ~5ms      ← 瓶颈
  Format+Render    ~3ms
  ─────────────────────
  用户看到         ~8ms 延迟

NTP PROTOCOL

NTP 报文解析

 48 字节 NTP v4 请求/响应:

 Byte 0:  [LI:2][VN:3=4][Mode:3=3] = 0x23
 Byte 1-39: 零填充
 Byte 40-47: Transmit Timestamp
             (64-bit, NTP epoch 1900)

 时间转换:
   ntp_seconds - 2208988800 = unix_seconds
   (2208988800 = 1900→1970 的秒数差)

OFFSET ALGORITHM

NTP 偏差计算

 t₁ = 发送请求时间 (客户端)
 t₂ = 接收请求时间 (服务器)
 t₃ = 发送响应时间 (服务器)
 t₄ = 接收响应时间 (客户端)

 offset = ((t₂-t₁) + (t₃-t₄)) / 2
 rtt    = (t₄-t₁) - (t₃-t₂)

 多次测量取中位数 → 更准确
 5 rounds × median → 最终 offset
